# Tallshot and your privacy

Tallshot needs two powerful permissions: **Screen Recording** (to see a window) and **Accessibility** (to find the scrolling area and scroll it). Here is exactly what it does with them, and how each promise is checked.

| Promise | How it's kept | How it's checked |
| --- | --- | --- |
| No network | The app contains no networking code and links no third-party code. | `scripts/check-privacy.sh` scans the source for networking APIs and the built app for network symbols and non-Apple libraries. CI runs it on every push and before every release. |
| Captures go only where you send them | The finished PNG (or, with Copy as text, its words as Markdown; or, for a text capture, the app's text as Markdown) is copied to the clipboard and saved to the folder you chose (Desktop by default). If you turn on PDF, Word or Markdown, those are built in memory and written straight into the same folder (no temp copy elsewhere). Those are the only files the app writes, apart from the optional diagnostic report below. When the PNG was saved, the clipboard also holds a link to that file, so apps that paste files (Finder, Mail) get the file itself; an app that pastes links as text shows its path, which includes your user folder's name. | The privacy check fails if any other file write, an atomic write (which stages a temp copy), a temp folder or a cache appears in the source. A test (`PrivacyTests.swift`) runs a simulated capture through the same code the app uses to build and save the four formats and the diagnostic report, once with diagnostics off, once on, and once as a text capture (Markdown, PDF and Word made from an app's text). It then looks inside every file changed since, in the temp folders, caches, Application Support, Preferences, Containers, Saved Application State and the top level of the Desktop: it decodes PNGs, unpacks PDF streams and unzips Word files, looking for the capture's pixels and a marker word. It must find them in the chosen folder and in a deliberately planted copy, and nowhere else. It does not cover the clipboard, the screen-capture step itself (that's in the app and needs a real screen), or copies macOS might make outside those folders. |
| File names leave out password fields and Incognito windows | By default a capture's files are named after the app, the window or page title and, in a browser, the site's domain (never the rest of the address), then the date and "Tallshot". Tallshot adds no title or domain when a password field has the keyboard (it checks only the field's type, never its contents) or the title marks a private window, such as Chrome's "(Incognito)". Chrome is the only browser known to mark its private windows that way, so in Safari, Arc, Firefox and others a private window's title can appear in the name. The name is used only as the files' names (and the diagnostic report folder's name). It is not written inside any file: the PDF's title is always "Tallshot capture", the Word file and the PNG carry no title or author, and the one place it shows up in a file's contents is the Markdown file's link to the PNG saved beside it, which has to use the PNG's real name. Settings → Output → File names → Date only leaves the app, title and domain out of the names entirely. | Tests in `CaptureNameTests.swift` cover each naming rule on made-up names, and `NameFactsTests.swift` runs the code that reads the window against a made-up app: a focused password field stops it before any title is read, Incognito, non-English Chrome, Chrome web-app windows and unfamiliar Chrome titles get only the app's name, and Tallshot's own window is never asked anything. `ReviewExportTests.swift` builds every format with a made-up title and domain in the name and checks that neither (nor your Mac user name) is inside the PDF's information or bytes, any part of the Word file, or the PNG, and that the Markdown file has it only in the link to the PNG. |
| Check This App only reads | **Troubleshooting → Check This App…** reads the front app's accessibility tree (the same as a text capture) and shows the first and last message only in its window. Its report, copied only when you click Copy Report, holds counts and the page's class names, never chat text. It takes no pictures, scrolls nothing and writes no files. | `scripts/check-capture-rules.sh` fails if the check, the tree reader or the chat text capture scrolls, posts events, moves the pointer, changes the app or writes files; a test checks the report has no chat text. |
| Text recognition stays on your Mac | For a searchable PDF, or Word and Markdown when the app doesn't share its text, Tallshot reads the words in the image with Apple's Vision framework, which runs on the Mac. | No network code (checked as above). |
| Diagnostics only if you ask | **Keep a diagnostic report when a capture stops early** is off by default. When you turn it on and a capture stops early, Tallshot saves a folder with its frames and a step log, next to the capture or in a folder you choose, so you can share it if you choose. It is never sent anywhere. | The test above checks that with the setting off a capture keeps no frames and no report can be written, and that with it on the report holds only the capture's frames and log in the chosen folder. The privacy check fails if the report can be written other than through the settings-guarded code, or if the setting isn't off by default. |
| Frames never touch the disk | Each picture taken during a capture lives in memory and is discarded when the capture ends. | The privacy check finds no temp files, caches or logs in the code and no temp-file symbols in the built app; the test above finds no copy of the capture in the temp folders or caches. |
| Captures only when you ask | The screen is read with one-shot screenshots between the hotkey and the end of that capture. There is no background stream and no timer. | The check fails on any continuous screen stream or background timer. macOS's purple screen-recording indicator shows only during a capture. |
| Protected windows stay protected | Windows macOS marks as private (password prompts, DRM video) come back blank from macOS. Tallshot uses them as returned. | macOS enforces this. |
| No analytics, no accounts | Settings are the only thing stored, in Tallshot's own preferences. For chat apps you checked with Check This App, that includes the app's ID and name, your answer and the date; never any chat text. | The check fails on analytics, crash-reporting or updater code, and on preferences other than settings. |

## Why not the App Sandbox?

The App Sandbox would let macOS itself block any network connection, which would be ideal. But Tallshot has to read the layout of *other* apps' windows through Accessibility and post scroll events to them, and save to the Desktop by default. The sandbox gets in the way of all three, and Tallshot can't work without them. So Tallshot uses Apple's **hardened runtime** with **no entitlements at all**, and the source and app scans above prove there is no networking code. A sandboxed build exists only as an experiment (`TALLSHOT_SANDBOX=1 scripts/build-direct.sh`) for checking whether a future macOS allows it.

## Browsers and Chromium/Electron apps

Chrome, Arc, Edge, Brave, Dia and Electron apps (many chat and notes apps) don't describe their windows to Accessibility until an assistive app asks. When you capture one, Tallshot turns that description on for that app (`AXManualAccessibility`, `AXEnhancedUserInterface`), the same switch screen readers use, and puts `AXEnhancedUserInterface` back the way it was when the capture ends. It reads where the scrolling area is. It reads the page's text only if you turned on Word, Markdown or Copy as text, and it reads the window title and page address to name the file, unless you chose date-only names.

For a **text capture** (the default when an app shares its whole text, such as a terminal or Notes), Tallshot reads one element: the text area under the pointer. It reads its role, frame, character count, which characters are on screen, and its text, and checks that it isn't inside a web page. It reads nothing else, takes no pictures and sends no scroll events. The text goes only to the clipboard and the folder you chose, like any capture. Settings → General → When an app shares its text → Always take a scrolling screenshot turns this off.

## Link commands

`tallshot://capture` starts a capture of whatever is under the pointer, so tools like Raycast and Shortcuts can trigger it. A web page could ask to open such a link too, but browsers ask you first, and the result goes only to your clipboard and save folder, never back to the page.
